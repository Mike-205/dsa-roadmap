# DSA Roadmap Project

A self-directed, first-principles DSA curriculum — not an interview-prep roadmap. Full rationale in `00-philosophy.md`.

## Structure

- `00-philosophy.md` — the core philosophy, what's rejected (LeetCode-as-curriculum), the primitive-before-abstraction learning pattern, candidate resources, and the 5-pass research plan.
- `passes/` — one file per research pass.
  - `01-pedagogy.md` — done. How MIT 6.006, Princeton, Open Data Structures, Erickson, and Nic Barker's video actually sequence/motivate concepts.
  - `01b-gap-check.md` — done. Learning-science backing for friction-first teaching (with a real caveat), Berkeley CS 61B, invention-history for 6 classic structures, Programming Pearls.
  - `01c-gap-check-2.md` — done. MIT 6.042 (formalization backbone), VisuAlgo, Kleinberg-Tardos, unlabeled-practice sources (AoC/Euler/Kattis), CS:APP's memory chapter + the Java cache-locality bridge.
  - `02-dependency-graph.md` — done. 42-node conceptual dependency graph (memory through NP-completeness), stripped of course/resource names, with named structures/algorithms attached only as exemplars.
  - `03-resource-mapping.md` — done. Each of the 42 concept nodes assigned to the resource(s) best suited for its intuition/formal/implementation/visualization/problem jobs, with per-node gaps flagged for Pass 4.
  - `04-curriculum.md` — done. All 42 nodes sequenced into 16 milestones (M0–M15) with dependency-checked ordering, resources, friction problems, formalization steps, implementation tasks, experiments, and review checkpoints.
  - `05-stress-test.md` — done. Design audit (not empirical — nobody has taken the curriculum yet) against three falsifiable signatures: checkpoint transfer distance, friction problems that name their own fix, and interleaved-vs-blocked practice. Verdict: partial fail, repairable.
- `sources/` — raw source material (transcripts, notes) pulled in to verify or deepen a pass's findings.
  - `nic-barker-transcript.md` — my summary of the video's content, cross-checked against Pass 1's other sources.

## Status

Pass 1 + 1b + 1c complete (2026-09-24). All originally-flagged gaps are now resolved. Key findings:

- Princeton, MIT 6.006, and Open Data Structures all independently teach a data structure as "an interface + a sequence of implementations, each fixing the prior one's bottleneck" (clearest example: Princeton's union-find, taught as quick-find → quick-union → weighted+path-compressed quick-union).
- Nic Barker's video independently arrives at the same friction-driven shape one level lower: array → sorted array → array list → stack → queue → linked list → hash map → tree → graph, each motivated by a named limitation of the last.
- Berkeley CS 61B gives an even more concrete on-ramp for the very first lesson (IntList → SLList via a sentinel node, directly quotable), with interfaces retrofitted after concrete implementations — the reverse of ODS's interface-first order.
- Learning science (Kapur, Schwartz & Bransford, Kirschner-Sweller-Clark) supports the friction-first bet, but attaches a real condition: struggle must be a scaffolded, well-designed problem followed by explicit formalization. This is now a design constraint for Pass 4.
- Invention history and Programming Pearls give real Pass-4 material (motivating-problem narratives, a worked "problem solving" example) but at different curriculum layers — history at the structure level, Pearls after fundamentals.
- **MIT 6.042** is the formalization backbone: has the induction/recurrence tools to prove AVL height and amortized array-list cost, and the exact probability machinery (birthday paradox via linearity of expectation) hashing's expected-case analysis needs. Pull in on-demand, not front-loaded.
- **VisuAlgo** is genuinely interactive and covers nearly everything researched, but only at the interface level — it doesn't visualize Barker's "it's all one array underneath" mechanism. That remains an open gap for Pass 4 to fill directly.
- **Kleinberg-Tardos** joins Erickson as a second problem-first algorithm-design text, with an even stronger opening (stable matching, with a genuine practice-before-theory history).
- **Advent of Code** is the best-fit "unlabeled, forces diagnosis" practice source for Pass 5's stress-test — introduce late, after arrays-through-graphs. Kattis (used untagged) as a second stage; Project Euler is the weakest fit (math-insight-driven, not representation-tradeoff-driven).
- **CS:APP Ch. 6 + a JVM-boxing/Project Valhalla explainer together close the Java cache-locality gap** flagged twice earlier: Barker's C-level intuition is correct in principle but needs the pointer-chasing/autoboxing bridge to hold for Java's reference-based collections.

Candidate synthesis for Pass 2: each concept node needs two layers — a mechanism-level explanation (Barker: what the array layout makes cheap/expensive) and a formal interface/cost-table treatment (Princeton/MIT/ODS/CS 61B). Barker's chain and CS 61B's IntList→SLList story are both ready-made candidate sequences, not just intuition.

Pass 2 complete (2026-09-24). Built as a 42-node graph, root at "memory as an addressable array," through named structures/algorithms attached only as exemplars (which resource teaches which exemplar is left to Pass 3). Two rules enforced throughout: `requires:` is a strict AND across every exemplar of a node (caught several false edges, e.g. a single "sorting" node falsely requiring both invariants and recursion — insertion sort needs neither), and no dangling or vague requirements (every `requires:` target is an actual node; this produced a small formal-tools track for induction, exchange arguments, probability, and reduction, pulled in on-demand rather than front-loaded). Key structural findings: recursion had to split into "recursive decomposition" (no structural requirement — covers array-based recursion like merge sort) and "self-referential structure" (requires decomposition + indirection — covers linked lists and trees); the contiguous-vs-indirect representation fork recurs at five separate scales (sequences, hash collision resolution, the array-backed binary heap, graph representations, memoization's cache choice) and is flagged as a candidate Pass 5 stress-test question; greedy and dynamic programming both rest on "optimal substructure" but diverge in whether they explore all choices or commit to one, and DP's overlapping-subproblems requirement had to be separated from optimal substructure since naive Fibonacci needs the former but isn't an optimization problem at all.
